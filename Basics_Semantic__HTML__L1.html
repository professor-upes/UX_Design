03

So what is the "Semantic Web"?

Semantic is just a fancy word for meaning.

A web page has two audiences. One is a human — your customer, scrolling on a phone. The other is a machine — Google's crawler, a screen reader used by a blind user, ChatGPT reading your site, a price-comparison bot.

Humans see colours, size and position, so they understand your page instantly. Machines see only your tags. If your tags carry no meaning, the machine is reading your page blindfolded.

➜ Think of a Nykaa product page.

➜ You see the price because it's big and bold. Google can't "see" big and bold.

➜ Google reads the tag around it. If the tag says <div> → "some box, no idea what."
If the tag says <article> or <time> → "ah, this is a product, this is a date."

➜ Semantic HTML = choosing tags that describe the content, not the look.

✗ Non-semantic (meaningless)

<div class="top">
  <div class="menu">Home</div>
</div>
<div class="main">
  <div class="title">Our Story</div>
</div>

Every box is a div. To a machine, this page is a pile of identical grey boxes.

✓ Semantic (meaningful)

<header>
  <nav>Home</nav>
</header>
<main>
  <h1>Our Story</h1>
</main>

Same page on screen. But now the machine knows: top bar, navigation, main content, main heading.

Why a business student should care: semantic tags directly affect SEO ranking, accessibility compliance (a legal requirement in many markets), and now whether AI assistants can read and recommend your brand. Same effort to type. Very different business outcome.

How a tag works (30-second theory)

<p>Hello students</p>
 ↑        ↑        ↑
opening  content  closing tag (note the / )

➜ A tag is a label wrapped around content.

➜ Almost every tag opens <p> and closes </p>. Forget the slash → the page breaks.

➜ A few tags don't need closing, e.g. <img> and <br>. They are "self-closing".

➜ Tags sit inside other tags — like boxes inside a carton. That's called nesting.

The 15 tags — the whole syllabus of today

Group A is the skeleton of a page. Group B gives meaning to text.

Group A — Layout / structure tags (7)

TagMeansReal example
<header>Top strip of the page or of a section — logo, taglineThe Zomato logo bar at the top
<nav>A group of navigation links (menu)Home · Menu · Offers · Cart
<main>The one main content area. Only one per pageThe restaurant listings themselves
<section>A themed chunk of content, usually with a heading"Top rated near you"
<article>A self-contained item that makes sense aloneOne restaurant card, one blog post
<aside>Side content — related but not essentialFilters sidebar, "You may also like"
<footer>Bottom strip — contact, copyright, policy links"© 2026 · Privacy · Careers"

➜ Confused between section and article?

➜ Ask: "If I cut this out and paste it in WhatsApp, does it still make sense on its own?"

➜ Yes → <article> (one boAt earphone card, one news story).
No → <section> ("Bestsellers" heading alone means nothing).

Group B — Text-meaning tags (8)

TagMeansNote
<h1> … <h6>Headings, h1 biggest idea → h6 smallestUse one h1 per page. Never skip levels
<p>A paragraph of textThe default home for any sentence
<ul> / <li>Unordered list and its list itemsBullet points — features, benefits
<strong>Genuinely important textLooks bold, but also tells machines "this matters"
<em>Emphasis — stress this word when speakingLooks italic, carries meaning
<figure> + <figcaption>An image with its official captionTies picture and caption together
<time>A machine-readable date or time<time datetime="2026-08-07">
<blockquote>A quotation from another sourceCustomer testimonials

➜ <b> vs <strong> — both look bold. <b> only paints it bold. <strong> says "this is important."

➜ Same story: <i> is just slanted, <em> means emphasis.

➜ Rule of thumb → always pick the one that carries meaning.

08

File naming — the rules that save you from broken websites

On your laptop, a bad filename is a small annoyance. On a live web server, a bad filename means a 404 page not found. Web servers are strict in ways Windows is not.

The 6 rules

#Rule✗ Wrong✓ Right
1Always add the extensionhomepagehomepage.html
2No spaces — everabout us.htmlabout-us.html
3All lowercaseAboutUs.HTMLabout-us.html
4Only letters, numbers, - and _price@list#1.htmlprice_list_1.html
5Homepage must be named exactly thisHome.htmlindex.html
6Name it by content, not by datefinal_final_v2.htmlcontact.html

➜ Why no spaces? A web address cannot carry a space. The server converts it to %20 — so about us.html becomes about%20us.html. Ugly, and it breaks links.

➜ Why lowercase? Windows thinks Home.html and home.html are the same file. A Linux web server — which hosts most of the internet — thinks they are two different files. Your site works on your laptop and dies after upload. Classic.

➜ Why index.html? When someone types your domain with no page name, the server automatically serves the file called index.html. That is a built-in convention, not a choice.

The two joining styles

hyphen-case (kebab-case)

about-us.html · product-list.html

Use for web pages and images. Google reads the hyphen as a word separator — better for SEO.

snake_case (underscore _)

sales_data.csv · user_login.py

Use for data files and code files. Google reads the underscore as glue, joining words into one — bad for page names.

➜ Simple rule to remember: hyphen for pages, underscore for data.

➜ Google sees about-us as "about us" (two words) but about_us as "aboutus" (one nonsense word).

Common extensions

.html — structure .css — styling .js — behaviour .jpg / .png — images .svg — logos, icons .json — data

Where to save it — the project folder

Never save loose files on the Desktop. Every website is a folder, and everything it needs lives inside that folder.

Documents/
└── chai-point/          ← the project folder (your website)
    ├── index.html       ← homepage. This exact name.
    ├── about.html
    ├── contact.html
    ├── css/
    │   └── style.css    ← all your styling
    ├── images/
    │   ├── logo.png
    │   └── shop-front.jpg
    └── js/
        └── script.js

➜ Steps: create the folder chai-point → open VS Code → File > Open Folder → pick it.

➜ Now the Explorer panel shows your project. Create new files with the 📄 icon inside it.

➜ Never open a single file alone — open the folder. Live Server and links only work properly this way.

➜ Why subfolders? With 40 images loose next to your HTML, you will lose your mind by week three.

The link between folders and code: when you write <img src="images/logo.png">, you are giving the browser directions from your HTML file. "Go into the images folder, find logo.png." Rename the folder, and the image disappears. Folder structure is not housekeeping — it is part of your code.

Go Live — what it actually does

After installing Live Server, look at the bottom-right blue bar. You will see Go Live. Click it. Your browser opens with your page.

➜ Without Live Server: double-click the file → address bar shows file:///C:/Users/...
That is your hard disk. You are reading a document, not visiting a website.

➜ With Go Live: address shows http://127.0.0.1:5500/index.html
That is a real web server running on your own laptop. Same conditions as the live internet.

➜ Best part: press Ctrl + S and the browser refreshes by itself. No more Alt-Tab-F5-Alt-Tab.

➜ Click Port: 5500 in the same blue bar to stop it.

⚠ 0   ✕ 0    Ln 12, Col 4 Go Live
↓ after you click it ↓
⚠ 0   ✕ 0    Ln 12, Col 4 Port : 5500

➜ click "Port : 5500" again to stop the server

Decoding http://127.0.0.1:5500

PartMeaning
http://The language browsers and servers speak to each other
127.0.0.1Also written localhost. It means "this computer, right here." Nobody else on the internet can reach it
:5500The port number — which door of your computer this website is being served from

➜ What is a port, really? Your computer is one building with one address (127.0.0.1). But many services run inside it at once.

➜ Ports are the numbered doors of that building. Live Server uses door 5500. A React app uses 3000. A database uses 3306.

➜ Same address, different door → no collision. That's the whole idea.

➜ "Port 5500 is already in use"? You left an old Live Server running. Close the old browser tab, or just accept the new port it offers (5501). Nothing is broken.

Later in this course you will replace 127.0.0.1 with a real domain and push this same folder to a host like Netlify or Vercel. Nothing about your HTML changes — only the address in front of it. That is why we get the folder and filenames right from day one.
